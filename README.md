# GoApsny: Stopgap

Интерактивный конструктор приставных пандусов IDLab (АИС, Сухум). Отдельное приложение, с картой GoApsny и лендингом не смешивается.

Задание: [docs/TZ.md](docs/TZ.md) (ТЗ Алхаса от 2026-11-04).

## Что уже лежит

`cad/` — расчёт пандусов на CAD-движке build123d 0.13.0. Модель строится в 3D, размеры деталей снимаются с неё.

- `ramp_model.py` — ровная площадка: `python ramp_model.py OUT 48 58 98` (высоты порога, мм).
- `ramp_skew.py` — порог разной высоты слева и справа: `python ramp_skew.py OUT 190 160`.
- `sheet_model.py`, `sheet_skew.py`, `render3d.py` — листы A4 и 3D-картинка из модели.

Правила расчёта (Алхас, 2026-10-31 и ТЗ 2026-11-04):

- ширина 900, уклон 1:6, фанера 18, доска 40;
- боковина у порога = порог − 18, основание = порог × 6 (на скосе — по высокой стороне);
- фанера одним листом, все резы 90°, размеры целыми мм;
- внутреннее ребро только при пороге больше 200 мм.

Черновиком приложения из ТЗ считается этот расчёт (Алхас, 2026-11-05: «мы здесь с тобой всё и делали»). Данные пандуса Красного Креста для сверки ещё не получены.

## Запуск расчёта

```
pip install -r cad/requirements.txt
cd cad && PYTHONPATH=. python ramp_skew.py out 85 70
```

## Живая оболочка и карта пандусов (2026-11-23)

Интерфейс переведён в парадигму приложения «Суфлёр АИС» (эталон: `alkhas72/suflyor-ais`). Расчёт, шаги мастера и тексты не менялись.

- Оболочка по умолчанию `data-skin=living` (`src/skin-living.css`, мастер и AR — `src/skin-living-intake.css`, `ar.html`). Четыре настроения `data-mood`: `sage` (по умолчанию), `orchid`, `lime`, `night`; выбор хранится в браузере (`src/mood.js`).
- Прежние виды открываются адресом: `?skin=classic` (в духе iOS) и `?skin=violet` (сиреневая проба).
- На компьютере приложение стоит в корпусе iPhone на витрине (`src/shell.js`, `src/shell.css`): страница-витрина загружает то же приложение в окне, поэтому вид телефона честный. «Во весь экран» раскрывает приложение на окно. `?shell=off` открывает приложение без витрины. На телефонах и планшетах витрины нет.
- Карта пандусов: `src/map.js` (экран), `src/ramps-layer.js` (весь Leaflet и подложки, заменяется одним файлом), `src/ramps-source.js` (вид записи и источники), данные в `data/`. Договор с картой доступности GoApsny описан в [data/README.md](data/README.md). Адрес `?view=map` открывает карту сразу.
- Замер в один клик: `?measure=1&place_id=…&name=…&address=…&lat=…&lng=…&return=…` сразу открывает мастер «Новый замер» с подставленным местом. Все параметры, кроме `measure`, необязательны; `return` принимается только для своих адресов и `goapsny.org`.

## Правки по проходу Алхаса (2026-11-25)

- Мастер «Новый замер» в пять шагов в его порядке: «Общий план», «Замеры», «Примерка», «Представьтесь», «Итоговая анкета» (`STEPS` в `src/intake.js`). Все три замера на одном экране в порядке показа: высота А, ширина, высота Б; снимки лежат в прежних слотах `hl`, `free`, `hr`, `overview`, `extra`, `fit` (`STEP_SLOTS`), формат заявки и PDF не менялся. Списка ролей нет: имя и телефон. Начатый черновик прежнего порядка открывается с первого шага, числа и фото в нём целы.
- «Как мерить» показом: `src/howto.js` и `src/howto.css`. Одна сцена на three.js в виде рендера конструктора; стоит в листе конструктора (раздел «Как мерить») и открывается с шага «Замеры». Плоских схем замера в приложении больше нет.
- Подсказка жестов у 3D: в конструкторе (`data-gest` в `src/ui.js`, видна до первого касания модели, дальше не появляется) и в примерке (`src/ar.js`).
- Единицы: во всех текстах миллиметры, как в полях ввода.
- Цвет: человеку показывается только название цвета по-русски. Марка краски и номер по вееру остаются в данных заявки и в PDF для мастерской.
- Жизнь в папке: все адреса относительные, поэтому приложение можно положить в папку другого сайта (например `/zamer/` внутри карты). Адрес папки без косой черты в конце исправляет `index.html`. Ссылка на примерку строится от адреса самого приложения (`arBase` в `src/intake.js`) и ведёт на `ar.html`. Одно исключение: GLB для Scene Viewer примерка берёт по адресу `/api/glb` от корня сайта, поэтому при переносе `api/glb.js` кладётся в папку `api/` того сайта, а его импорты направляются на новое место `src/ramp.js` и `src/ar.js`. Ключи браузера остаются с приставкой `goapsny-stopgap:` (и `stopgap-ar-paint`, база IndexedDB `goapsny-stopgap-intake`), с ключами карты не пересекаются.

Вернуться можно тремя способами, от быстрого к основательному:

1. **Vercel, без кода.** В проекте `goapsny-stopgap` открыть Deployments, найти прежнюю боевую сборку (коммит `3b356db`) и нажать Instant Rollback. Главный адрес за минуту показывает прежнее приложение, код не меняется.
2. **Git.** PR сливать обычным слиянием, не squash: тогда всё изменение отменяется одним `git revert -m 1 <коммит слияния>` в новом PR. Коммиты `519c25d` и `3b356db` остаются в истории навсегда.
3. **Внутри нового приложения.** Прежние оболочки открываются адресом: `?skin=classic` и `?skin=violet`; `?shell=off` убирает витрину на компьютере. Расчёт пандуса один и тот же во всех видах.

Метки git на прежние состояния (ставит владелец репозитория, у облачной сессии права на метки нет):

```
git tag -a stopgap-v0.1 519c25d -m "Stopgap v0.1, 2026-11-05"
git tag -a stopgap-v0.2-classic 3b356db -m "Stopgap до живой оболочки, боевой сайт на 2026-11-23"
git push origin stopgap-v0.1 stopgap-v0.2-classic
```
